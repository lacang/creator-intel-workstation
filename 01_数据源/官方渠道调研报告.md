> 触发原因：抖音「模拟扫码登录 + 登录态 cookie + 拦截 API 响应」方案反复失败（二维码静默轮换、新设备二次验证、验证码失效），用户判断该路径不可持续，要求改研究官方渠道。

> 本轮红线（严格未越界）：**不注册、不申请资质、不采购、不试用、不采集、不改写既有交付物**。仅调研与汇报，等用户确认后再动。

## 一、结论先行

1. **停掉模拟登录是对的，而且理由比「扫不上码」更硬。** 该技术路线在《抖音用户协议》下被禁止，且 2024–2025 年已有生效刑事判例，认定「获取 X-Bogus/a_bogus 等反爬参数并避开平台安全保护措施、批量抓取」构成犯罪 —— 与我们 `douyin_collector.py` 依赖的签名机制高度重合。继续投入不是运气问题，是合规问题。
2. **官方渠道存在，但和本项目核心诉求存在根本性错配。** 抖音开放平台所有「用户/视频/评论数据」接口的设计目标是「让开发者帮**授权用户管理他自己的账号**」，**不提供读取任意第三方公开创作者的接口**。而 V1.0 的 P2/P3/P4 要的正是「批量观察他人创作者」——这一块纯官方 API 给不了。
3. **官方渠道里唯一能直接喂饱本项目的是「大盘/趋势类」数据**：热点榜、垂类达人榜、星图达人指数/热榜、影视综榜、巨量算数洞察报告。这些不需要目标创作者授权，正好对应 `trends` / `topic_opportunities` / `content_analysis` 三张表，且部分标注「限时免费」。
4. **有一条不用再折腾、零资质零费用就能往下走的路**（见第七节路线 A）：把 V1.0 重定位为「趋势 / 选题情报站」，用官方大盘数据 + 已实测免登录的公开源（B站热门、微博热搜、百度热榜）驱动，P1 的 8 表设计基本可复用。

## 二、为什么必须停止模拟登录（技术 + 法律）

### 2.1 技术侧：已实测的失败链路

| 环节 | 结果 |
|---|---|
| 抖音网页直连 | 返回 2397B JS 空壳；作品 API `403 Blocked by ArgusSecurityPlugin`（强制 a_bogus/X-Bogus/Uifid 签名）[见既有 P0 报告] |
| 真实浏览器 + 扫码 | 二维码自动静默轮换（旧快照必然过期）、新设备二次验证反复触发 |
| 短信验证码 | 双重叠 React 受控 `<input>`，`fill`/键盘/`value setter` 三套方案才填进去；仍因时效作废 |
| 登录态 cookie 落盘 | **自始至终未成功**（多次实测 `_dbg_cookies.json` 中无 `sessionid`/`sid_tt` 等） |
| 稳定性 | 每轮都需真人扫码 + 收短信，无法无人值守；任何一环改版即断 |

结论：即使某次侥幸成功，也**不具备「每期自动采集 30 创作者 / 200 作品」的工程可用性**。

### 2.2 法律侧：生效判例（关键）

| 判例 | 认定 | 与本项目的关联 |
|---|---|---|
| 湖南郴州北湖区法院，2024-12 生效 [1][2] | 用爬虫软件批量获取抖音用户数据，4 人以**非法获取计算机信息系统数据罪**（刑法 285 条）判 1 年 3 个月–3 年 6 个月 + 罚金 | 明确「自动化批量获取抖音数据」的刑事风险 |
| 江苏建湖县法院 / 检察院，2025 报道 [3] | 涉案软件**非法获取平台反爬参数「X-Bogus」等、避开服务器系统安全保护措施**批量抓取昵称/评论，被认定「专门用于侵入计算机信息系统的程序、工具」；3 人获刑、公司罚金，涉案违法所得 2317 万余元 | **直接命中**本项目依赖的签名参数与「拦截 API 响应」思路 |
| 南通海门区法院，2026 报道 [4] | 直播间自动抓取用户主页资料，以「提供侵入计算机信息系统程序罪」判刑 | 说明「只抓公开可见字段」不构成免责事由 |

同时《抖音用户协议》明确禁止「使用自动化手段访问、抓取平台内容」[5]。

> ⚠️ **对既有 P0 报告的更正（重要）**：`01_数据源/数据源测试报告.md` 第 29–33 行、63–67 行及第四节把「浏览器自动签名 + 用户登录态 cookie 拦截 API 响应」定性为「授权数据、非绕过反爬、属合规」。**该定性不成立**：判例 [3] 已把「获取反爬参数 + 避开安全保护措施」本身认定为侵入，与使用谁的账号、是否登录无关。建议将该方案状态由「已批准可用」改为「**已停用 / 不启用**」。
> 同理 `00_项目管理/第一阶段任务追踪.md` 中「待用户决策 2：提供抖音登录态 cookie」已作废。

### 3.1 官方 API 的硬约束（原文要点）

- 「使用限制：**需用户授权**」「权限范围：针对**审核通过的用户**开通权限」[7]

- 综上：**个人身份 + 想看别人账号 = 官方 API 完全无解**。

## 五、根本性错配：官方 API ≠ 竞品情报

| 本项目 V1.0 诉求 | 官方 API 能提供 | 差距 |
|---|---|---|
| P2：观察 **30 个他人**创作者档案 | 只有授权用户自己的档案 | ❌ 无法覆盖 |
| P3：**200 条他人**作品 + 深拆 30 | 只有自己账号的作品 | ❌ 无法覆盖 |
| P4：**10 作品评论**用户需求 | 只有自己公开视频下的评论 | ❌ 无法覆盖 |
| P5：趋势 / 话题机会（10 候选 / 3 重点） | 热点、垂类榜、行业报告、指数 | ✅ **可覆盖**（第三/四节渠道 2、3、5） |
| `content_analysis`（内容特征分析） | 官方报告 + 少量人工样本 | 🟡 可半自动 |

**这不是「再找个接口」能解决的**：抖音有意把 API 设计成「自家数据看板」，把「全平台公开数据洞察」留在巨量算数这类**人用产品**里，把「竞品批量明细」让给**商业数据服务商**。三者是刻意的商业分层。
