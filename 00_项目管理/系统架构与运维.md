> 面向"接手就能看懂、改得动、查得清"。配套 `第二轮大规模优化审计报告.md`。
> 更新时间：2026-11-11 14:35 CST

## 一、一句话架构

**14 个免登录公开数据源 → 分级采集 → SQLite（原始/派生分离）→ Flask 实时看板 + 离线快照**，由系统级 cron 每 2 分钟驱动，任一层挂掉都有自愈与如实告警。

```
crontab(*/2, @reboot)  →  /usr/local/bin/ws_maintain.sh  [语法预检]
                              ↓
                     tools/maintain.py（每步独立容错）
   1 采集（STALE>90s）→ 2 算健康 → 3 质量自检 → 4 导静态快照
   → 5 清 raw / 清历史明细 / 每日备份 → 6 拉起看板服务 → 7 留痕
                              ↓
              tools/collector.py::run_once()
   按 ORDER 遍历 14 源 → 分级节流（未到间隔写 scheduled_skip）
   → adapter 请求 → raw 落盘 → ingest（新增/处理分离）→ 统一聚合
   → 派生（内容速览 / 选题机会 / 关注词快照）
                              ↓
        database/workstation.db (WAL, 12 表, 13 显式索引)
                              ↓
   tools/dashboard.py  ← 实时服务 0.0.0.0:8765（waitress，15s 刷新）
        └─ --export → 创作者情报看板.html（离线快照，数据内联）
```

## 二、模块职责（改代码先看这张表）

| 文件 | 职责 | 不该放什么 |
|---|---|---|
| `tools/collector.py` | 编排、入库、派生、索引、保留策略；6 个基础源适配器 | 新数据源的具体解析逻辑（放 `sources_ext.py`） |
| `tools/sources_ext.py` | 8 个扩展源适配器 + `ORDER` / `LABELS` / `RAW_DIRS` / `SOURCE_META` 注册表 | 入库/派生逻辑 |
| `tools/textmatch.py` | 话题归一化、`shingles`、精确+受控模糊共振、关注词命中 | 业务排序、UI 文案 |
| `tools/dashboard.py` | 数据聚合函数 + 页面模板（CSS/JS 内联）+ CSV/JSON 导出接口 | 采集逻辑 |
| `tools/maintain.py` | 自愈闭环、连续性计算、raw/DB 清理、备份、服务 watchdog | 数据源解析 |
| `tools/verify.py` | 数据质量自检 → `logs/quality.json` | 修数据（它只读） |
| `tools/audit.py` | **只读**端到端审计（19 项） | 任何写操作 |
| `tools/scheduler.py` | 可选的常驻调度（手动验证用），生产以 cron 为准 | — |
| `tools/_deprecated/` | 已停用的扫码登录/签名链路，仅作历史证据 | 不要启用 |

## 三、配置（`config/` 三个文件，改完下一轮维护自动生效）

| 文件 | 控制什么 |
|---|---|
| `settings.json` | `interval_seconds=120`；每个源的 `enabled` / `tier` / `min_interval_seconds` / 特有参数；`request` 超时重试限速；`retention` 保留天数；派生开关 |
| `keywords.json` | 24 个赛道词，每轮对 7 平台热榜做包含匹配，命中 0 也写快照保证时序完整 |
| `creator_profile.json` | 账号画像 + 6 类叙事信号词与改编角度。看板「今日情报简报」据此把热榜收敛成"你能拍什么"。**不认同就直接改这个文件，不用改代码** |

配置合并是**递归深合并**：只写要覆盖的字段即可，新增源自动继承默认值。

## 四、分级调度（实时性的核心）

| 层级 | 间隔 | 源 | 理由 |
|---|---|---|---|
| 快线 | 120s | 抖音主榜/镜像、微博、百度实时、头条、网易、知乎、B站热搜词 | 轻量（每个 <0.5s），直接决定"现在该追什么" |
| 慢线 | 300s | B站全站榜、热门、分区榜 | 含作品指标快照，数据量大 |
| 慢线 | 600s | B站关键词搜索 | WAF 最严，单独降频 + 412 专项退避 |
| 日更 | 3600s | 百度垂直分榜、B站入站必刷 | 变化极慢，没必要每轮抓 |

cron 每 2 分钟触发一次 `run_once()`；每个源查 `collection_runs` 里自己上次成功的时间，未到间隔就写 `scheduled_skip` 后跳过。**跳过不是失败**，看板与健康/成功率统计都已区分。

`FRESHNESS_SECONDS = 600`（collector 单一真源）：末轮距今超过 10 分钟 → 看板红字、`maybe_self_heal` 触发补采、verify 报 issue。

## 五、数据库口径（最容易搞错的地方）

| 表/字段 | 口径 |
|---|---|
| `trends.heat_available` | 1=平台提供热度；0=平台不公开（网易/知乎），`heat_value` 为 NULL。**不是 0 度**，质量自检据此区分设计口径与缺陷 |
| `collection_runs.items_collected` | **真实新增**条数（V2 起） |
| `collection_runs.items_seen` | 本轮看到的条数（去重前）。历史 345 条记录该列为 DEFAULT 0，未回填，审计分开统计 |
| `collection_runs.status` | `success` / `partial` / `blocked` / `scheduled_skip` |
| `creator_snapshots.source` | V2 起统一为 `aggregate`：在**所有作品源入库后**按本轮全部作品快照聚合一次。历史分片记录保留原样 |
| `creator_snapshots.follower_count` | 留空。公开榜单不提供粉丝数，绝不估算填充 |
| `content_analysis` / `topic_opportunities` | `data_status='derived'`、`confidence=low`，规则引擎生成，**需人工二次筛选** |
| `comments` | 刻意为空（PII 合规） |
| `source_catalog` | 数据源目录：名称/平台/分级/间隔/提供内容/合规声明，看板与审计直接查 |

**派生数据的诚实性约定**：模糊共振 `match='fuzzy'` 带 `evidence`（共现片段），优先级降一级，文案写「需人工核实」；一句话结论优先引用 `match='exact'`。

## 六、如何新增一个数据源（照抄这 4 步）

1. 先用真实请求确认：**免登录、公开可访问、无需签名/验证码、不含 PII**。需授权的一律不接。
2. 在 `tools/sources_ext.py` 写 `a_xxx(http, cfg, seed) -> {"source","url","ok","note","items"}`；`items` 里 `kind='trend'` 或 `kind='work'`，字段见同文件 `_trend()` / `_bili_work()`。
3. 把源登记进 `ORDER` / `LABELS` / `RAW_DIRS` / `SOURCE_META` / `ADAPTERS`，并在 `config/settings.json` 写 `enabled` 与 `min_interval_seconds`。
4. 跑 `python3 tools/collector.py --once` → `python3 tools/audit.py` → 打开看板确认。**不要跳过实测**。

## 七、自愈与防呆（都踩过坑）

| 机制 | 位置 | 防的是什么 |
|---|---|---|
| 语法预检 | `ws_maintain.sh` | 代码热更新中间态被 cron 抢跑（14:00 真实事故） |
| 每步独立 try/except | `maintain.py` | 单点失败连带跳过服务拉起（08:55 事故） |
| `/api/version` 代码指纹 | `dashboard.py` | 代码改了服务仍跑旧版 |
| 重启后回验端口 | `maintain.py::ensure_web()` | 报了 restarted 其实没起来 |
| 实时健康计算 | `dashboard.py::data_continuity()` | `health.json` 冻结成假绿 |
| 前端二次核对 | `drawContinuity()` | 静态快照/服务挂掉时显示假绿 |
| 请求触发补采 | `maybe_self_heal()` | cron 死了但服务还在 |
| `@reboot` + shell 钩子 | crontab / `/usr/local/bin/ws_watchdog*.sh` / `/etc/profile.d` / `/etc/zsh/zshenv` | 沙箱休眠恢复后无人拉起 |
| 口径自愈 UPDATE | `ensure_extra_tables()` | 热度可得性脏标记（13:55 事故） |

**休眠期间的空窗无法补造**：VM 冻结时没有任何进程能运行，这是平台限制。系统目标只能是「恢复后尽快自愈」+「停滞如实可见」，历史空窗在看板永久保留。

## 八、日常运维命令

```bash
cd /workspace/创作者情报工作站

python3 tools/audit.py                       # 19 项只读审计（首选）
python3 tools/collector.py --once            # 手工补一轮
python3 tools/verify.py                      # 质量自检
python3 tools/dashboard.py --export          # 重导离线快照
python3 tools/dashboard.py --port 8765       # 前台起实时看板

crontab -l                                  # 调度是否还在
tail -20 /tmp/ws_maintain.log               # 每轮维护留痕
curl -s http://localhost:8765/api/version   # 服务加载的代码版本
cat logs/health.json && cat logs/quality.json
```

CSV/JSON 导出：看板「数据导出」区，或 `/api/export/<表名>.csv`、`/api/export/all.json`（白名单，越权 404）。

## 九、合规红线（不可协商）

仅请求免登录、公开可访问的官方榜单/热点接口；不带登录态/cookie；不生成或伪造 `a_bogus` / `X-Bogus` / WBI 等签名；不触发或绕过验证码/二次验证/设备校验；不采集含实名/手机号等 PII 的数据；不采购/注册商业服务或谎报已付费。

所有入库记录带 `source / source_url / collected_at / data_status` 四件套；原始响应按任务书分层落 `03/05_*/raw/`；原始表与派生表分离，派生数据绝不回写原始表。
