# 主持人智库（Knowledge Base）设计方案 · V4 单人自拍口播工作台

> 对应一次方向性复盘：原「实时热榜监视器」对**尚未起号的电台/播客主持人**赋能有限——
> 它只回答「今天什么热」，不回答「我作为主持人，起号前该准备什么、攒哪些可复用的框架和选题」。
> 本轮把系统从「监视器」升级为「**记忆 + 准备系统**」。

## 一、为什么之前不够、这次改了什么

| 维度 | 之前（监视器） | 现在（主持人智库） |
|---|---|---|
| 核心问题 | 今天什么热？ | 我作为主持人，能讲什么、该准备什么？ |
| 用户画像 | 瞎猜「逸博故事多/故事向」 | 真实身份：电台/播客主持，尚未起号 |
| 数据命运 | trends 按 7 天清理、看完即弃 | 沉淀进 `knowledge_base`，越积累越值钱 |
| 产出 | 热点列表 | 定位卡 + 框架库 + 常青选题库 + 起号准备清单 |
| 视角 | 泛泛「可改编」 | 按主持人能力（声音叙事/访谈/长内容）给电台视角角度 |

合规边界不变：仅免登录公开热榜；角度为规则派生、标注需人工筛选；不登录、不签名、不绕验证码、不采 PII。

## 二、三层架构

```
热榜采集(14源/7平台)
      │  每轮主榜趋势
      ▼
[1] 主持人能力库 host_assets        声音叙事/访谈拆解/长内容/追问/共情（5 项，带强度分）
[2] 内容框架库 content_frameworks    开场声音钩子/访谈式拆解/故事化长叙事/观点交锋/人物特写（5 个）
      │  命中赛道信号词 → 匹配能力 + 框架 → 生成电台视角角度
      ▼
[3] 智库主表 knowledge_base         跨轮/跨平台反复出现 → durability 累加 → 自动晋升常青
```

## 三、数据模型（3 张新表）

- **host_assets**：`asset_key, name, maps_to, strength, description`。从 `config/host_profile.json` 按 key 幂等播种。
- **content_frameworks**：`fw_key, name, fit_asset, fit_asset2, structure, hook_example`。同样按 key 播种。
- **knowledge_base**：智库沉淀核心。关键字段
  - `nk`（归一化话题）+ `category` 联合唯一，保证同一话题跨轮合并、不重复膨胀；
  - `durability`（沉淀强度，每轮复现 +1，新平台出现再 +1）、`rounds_seen`（在榜轮次）、`platforms_seen`（JSON）；
  - `asset_key`/`framework_key`/`angle`（主持人视角改编角度，规则生成）；
  - `status`：`incubating` → `validated`（常青）→ `ready`（待拍，用户手动策展）。

## 四、沉淀机制（数据怎么变成智库）

每轮 `run_once` 末尾调用 `knowledge.incubate(conn, round_ts)`：

1. 取末轮主榜趋势（与简报同口径 `PRIMARY_SOURCES`，避开镜像/垂直榜稀释）；
2. 每条趋势按 `host_profile.json` 的 `narrative_categories` 信号词匹配首个类别；
3. 命中后按「类别 → 主持人能力 + 内容框架」合成电台视角角度；
4. 以 `(nk, category)` 聚合，取最佳榜位/最高热度、平台去重；
5. 已存在则 **累加** durability / rounds_seen / platforms，追加 source_refs；不存在则新建为 `incubating`；
6. **自动晋升**：出现 ≥3 轮、或命中 ≥3 平台、或 durability ≥4 → `status='validated'`（常青）。
   用户可在看板点「标为待拍」把 validated 升 `ready`（不覆盖自动沉淀）。

> 关键差异：trends 是「易逝」的（7 天清理），knowledge_base 是「耐久」的（独立表、不被清理）。
> 同一话题反复出现，其洞察留在智库，原始热榜清掉也不影响。

## 五、看板入口：起号准备工作台

首屏第二位新增「**起号准备工作台 · 主持人智库**」面板（高频监控折叠到底部，准备台前置）：
- **定位卡**：你是谁 / 一句话 / 起号定位草稿 / 适合形式；
- **主持人能力库** + **内容框架库**（含结构说明与开场示例）；
- **常青选题库**（已验证、可反复做）+ **孵化中选题**；
- **起号准备清单**：定位/能力库/框架库/常青≥5/待拍≥1，进度条直观显示还差什么。

每条选题点「标为待拍 ▸」经 `POST /api/kb/<id>/promote` 升级为 ready。

## 六、自检与审计

- `verify.py` 新增第 11 组：资产/框架播种、KB 增长、max_durability 晋升阈值。
- `audit.py` 新增 G 组（主持人智库）：4 项检查，全部 PASS。
- 终检（本轮）：审计 22 PASS / 1 WARN / 0 FAIL；质量自检 95 分 0 错误；KB 累计 72 条、常青 54、孵化 18。

## 六·五、内容安全守门（非破坏性）

实时热榜常混入时政/敏感话题（总书记、外交部、台办/台当局、赖清德、特朗普/拜登、apec 等）。
把它们当成「个人创作者的内容选题」推荐，既不赋能又踩红线。因此新增一层**内容安全拒识**：

- 配置：`config/content_safety.json` 的 `deny_patterns`（可人工增删，enabled 可整体关闭）。
- 沉淀侧（`knowledge.incubate`）：命中拒识清单的热榜话题**不进入匹配**，既不写入题库、也不累加 durability。
- 展示侧（`dashboard.data_knowledge_base`）：已在库中的命中条目**不进入推荐面**（常青/孵化/全部列表均过滤），
  仅返回 `excluded_sensitive` 计数，并在智库说明里透明标注「已按内容安全策略隔离 N 条时政/敏感话题」。
- **非破坏性**：底层 `trends` 实时数据与已入库条目**原样保留、不删除、不改写**，只是不再作为选题推荐给个人创作者。
- 实测：13 条敏感话题全部隔离，推荐面 0 泄漏；`新疆一车主洗车` 这类民生/趣闻**不误伤**（清单只收时政关键词，不含裸地域名）。

> 审计/自检：G 组（主持人智库）+ 第 11 组仍全绿；本轮复核审计 23 PASS / 0 WARN / 0 FAIL，质量 95 健康 / 0 错误。

## 七、后续可做（未在本轮实现）

- 用户手动给常青选题写 `user_notes`（口播脚本骨架/落点），形成「可拍脚本库」；
- 框架库支持用户增删，沉淀成个人方法论；
- 起号后把「常青选题」与真实发布数据回连，验证哪类框架转化更好（需用户授权且合规）。

## 八、V4 重构：从「电台主持」到「单人自拍口播」

### 8.1 方向重定（最关键的一次升级）

用户明确整体方向为 **单人自拍口播（尚未起号）**，理由：该赛道是最不易被 AI 替代、且个人 IP 最大化的一类内容形态——真人出镜、口语化、对着镜头说话，依赖镜头表现力、观点提炼与情绪调动，无法被生成式模型平替。

> 系统不做"替你生成口播稿"，而是做"**替你攒可复用的镜头能力 + 可拍框架 + 常青选题**"的准备系统。所有角度均为规则派生、标注需人工筛选。

因此 V4 把 V3 的「电台/播客主持」语义全部改写为口播语义：

| 维度 | V3（电台主持） | V4（单人自拍口播） |
|---|---|---|
| 身份 | 电台/播客主持，尚未起号 | 单人自拍口播创作者，尚未起号 |
| 能力库 | 声音叙事/访谈/长内容 | 镜头表现力/口语化表达/观点提炼/情绪调动/人设一致性/即兴反应/结构把控（7 项） |
| 框架库 | 开场声音钩子/访谈式拆解 | 黄金3秒钩子/观点三幕/故事化口播/人设锚点/情绪递进/互动留白/反常识开场（7 个，每框架含 4 步可拍脚本骨架） |
| 类别 | 观点·对话 等 6 类 | 观点·立场线/人物·命运线/社会·观察/文化·漫谈/生活·情绪/突发·现场（6 类，信号词扩充口播向词） |
| 角度文案 | 「镜头前用…（匹配能力）」 | 同上，强调真人出镜与真人 IP |

### 8.2 四大升级（审计 / 逻辑 / 合规 / 实用性）

- **审计（audit.py，8 组 A–H）**：新增 **G 组（口播智库）**——校验口播能力库语义（含镜头表现力/口语化表达/黄金3秒钩子/观点三幕）、框架库含脚本骨架、智库沉淀无悬空 framework/asset 引用（4 项检查）；新增 **H 组（内容安全）**——拒识清单存在且启用、推荐面敏感话题经 API 实际下发视图核验隔离、合规声明。终检 **27 PASS / 0 WARN / 0 FAIL**。
- **逻辑（匹配与晋升）**：类别匹配由「命中第一个」改为 **`best_cat(kw)` 命中信号词最多者最贴切**；晋升阈值保持可解释——在榜≥3 轮、或命中≥3 平台、或 durability≥4 → `validated`（常青）。
- **合规（content_safety.json）**：`deny_patterns` 扩充至 42 条（含总书记/外交部/台办/台当局/赖清德/特朗普/拜登/apex/APEC 等），`enabled=true`；非破坏性守门——命中敏感话题不进推荐面、不累加 durability、底层数据原样保留，仅返回 `excluded_sensitive` 计数并透明标注。
- **实用性（dashboard 前端）**：bench 标题改「单人自拍口播智库」；数据源覆盖 18 源 / 7 平台；新增「今日口播选题」块（常青 durability 最高前 6）；框架库新增 `.skel` 脚本骨架渲染；每条选题新增 `.script` 口播脚本骨架（绿色视觉，换行转 `<br>`）；看板 `/api/all` 的 `knowledge` 返回 `picks / evergreen / incubating / excluded_sensitive / all` 等字段。

### 8.3 信息源扩充（18 源 / 7 平台）

在保留抖音/微博/百度实时/头条/网易/知乎/B站主榜基础上，**百度垂直分榜新增 4 个免登录可采源**：finance（财经）、car（汽车）、travel（旅游）、technology（科技），共 8 个百度垂直 tab（novel/movie/teleplay/game/finance/car/travel/technology）。经实测均免登录可采（各 30~46 条），成功沉淀进 KB。

`PRIMARY_SOURCES` 显式固定真源清单，避免镜像/垂直榜稀释主榜口径；百度垂直源作为「口播优质选题燃料」按日更（3600s）调度入库。

### 8.4 选题库沉淀：幂等重对齐迁移（_realign_kb_to_profile）

host_profile 改版后，已沉淀 KB 行需按「类别 → 新能力 / 新框架」重对齐 `asset_key / framework_key / angle`。设计为**幂等、仅改派生字段（不改 nk/category/durability/status）**：

- 含类别改名映射（观点·对话 → 观点·立场线、生活·叙事 → 生活·情绪）；
- RENAME 处理 `UNIQUE(nk, category)` 冲突：若新类别已存在该 nk，则 DELETE 旧行，否则 UPDATE；
- 重对齐后最终 **0 悬空 framework/asset 引用**，KB 仅剩 6 个新类别名。

- 审计 27 PASS / 0 WARN / 0 FAIL；质量自检 95 分 / 0 错误；
- 信息源 18 个 / 7 平台已注册；KB 常青 + 孵化 + 全部列表经内容安全过滤 0 泄漏；
- 看板 `/api/all` 实测：`picks` 6 条、`evergreen` 12、`incubating` 12、`excluded_sensitive` 10、`all` 40，pick 已带口播框架/能力/脚本骨架。
